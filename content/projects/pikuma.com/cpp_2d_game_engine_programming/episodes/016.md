## 核心概念

### 1. `Game` 类的生命周期

`Game` 类对外暴露一组**有序的生命周期方法**，`main.cpp` 只需按顺序调用：

```cpp
Game game;          // 构造函数：对象诞生
game.Initialize();  // 初始化（窗口、SDL、渲染器等，目前为空）
game.Run();         // 进入游戏循环（内部死循环，目前不会退出）
game.Destroy();     // 清理资源（目前为空）
// 离开作用域 → 析构函数调用
```

这套顺序几乎是所有游戏引擎的标准范式：
- **Initialize()** —— 启动子系统、创建窗口/渲染器、加载初始资源。
- **Run()** —— 进入主循环，每帧重复 *ProcessInput → Update → Render*。
- **Destroy()** —— 释放 Initialize 阶段申请的资源（SDL 窗口、OpenGL context 等）。

### 2. 游戏循环（Game Loop）

`Run()` 内部就是经典的**游戏循环**，每一帧依次执行三个阶段：

```cpp
void Game::Run()
{
    while (true)
    {
        ProcessInput();  // 1. 采集输入（键盘/鼠标/手柄）
        Update();        // 2. 更新世界状态（物理、AI、实体位移）
        Render();        // 3. 绘制当前帧
    }
}
```

> [!important] 为什么分成这三步？
> 把“读输入 → 改状态 → 画画面”解耦，是游戏引擎最基础的关注点分离（[[Separation of Concerns]]）。
> - **ProcessInput**：只负责“知道用户做了什么”，不改世界。
> - **Update**：只负责“根据输入和时间推进世界”，不画图。
> - **Render**：只负责“把当前世界画出来”，不改状态。
>
> 后续引入 [[帧率控制|帧率限制 / delta time]]、[[固定时间步长|固定时间步长 (fixed timestep)]] 时，这个结构能干净地承载它们。

> [!warning] 当前的死循环
> 现在 `while (true)` 没有任何退出条件，一旦运行 `main` 程序会卡死在循环里，`Destroy()` 与析构函数都**不会被执行**。后续 episode 会引入“窗口关闭 / ESC 退出”的 `isRunning` 标志来打破循环。

### 3. 构造函数与析构函数

```cpp
Game::Game()
{
    std::cout << "Game constructor called!" << std::endl;
}

Game::~Game()
{
    std::cout << "Game destructor called!" << std::endl;
}
```

目前只打印日志，用于**验证对象的生灭顺序**。这其实是在为后续的 [[RAII]]（资源获取即初始化）打基础：构造时申请、析构时释放。

> [!note] 调试观察
> 由于上面的死循环，运行后你只会看到 `Game constructor called!`，看不到 destructor 那行——因为程序根本走不到 `return 0;`。这恰好是引入退出标志的动机。

## `main.cpp` 的角色变化

```cpp
#include <iostream>
#include "game.h"

int main(int argc, char *argv[])
{
    Game game;

    game.Initialize();
    game.Run();
    game.Destroy();

    return 0;
}
```

`main` 从“干活的”退化成了**启动器（bootstrap）**：只负责创建 `Game` 实例并驱动它的生命周期。所有真正的引擎逻辑都搬进了类里。这是良好的分层——`main` 越薄越好。

## CMake 变更

```cmake
add_executable(main
    "src/main.cpp"
    "src/game.cpp"   # ← 新增
)
```

新增源文件后记得加进编译目标，否则链接器找不到 `Game` 的实现。此处 `main` 是个普通可执行文件 target，不是库。

## 代码骨架总览

```cpp
// game.h
#pragma once

class Game
{
private:
    // ...（未来放窗口、渲染器、isRunning 等成员）
public:
    Game();
    ~Game();
    void Initialize();
    void Run();
    void ProcessInput();
    void Update();
    void Render();
    void Destroy();
};
```

`private` 区目前是空的占位 `// ...`，为后续成员变量（如 `bool isRunning`、SDL 窗口指针、渲染器等）预留。

## 要点总结

- ✅ 引入 `Game` 类作为引擎的**中心协调者**，所有逻辑收敛于一处。
- ✅ 确立生命周期：`Initialize → Run → Destroy`。
- ✅ 确立游戏循环三阶段：`ProcessInput → Update → Render`。
- ✅ `main.cpp` 瘦身为纯启动器。
- ⏳ 当前 `Run()` 是无退出条件的死循环，是下一步要解决的问题（`isRunning` 标志）。
- ⏳ 析构函数暂未触发，资源清理逻辑待补。

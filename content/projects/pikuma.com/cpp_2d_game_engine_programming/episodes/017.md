# Episode 017 — 创建 SDL 窗口

> [!summary] 一句话总结
> 给 搭好的 `Game::Initialize()` 骨架填上**第一笔真实逻辑**：用 SDL3 初始化视频子系统，创建一个 `800×600` 的无边框窗口和与之配套的 2D 渲染器——引擎第一次在屏幕上“开了扇窗”。

## 概述

Episode 016 留下的 `Game` 类生命周期是空的壳：`Initialize()` / `Destroy()` 里什么都没有，`Run()` 是个死循环。本集把 SDL 接进来，让 `Initialize()` 真正干活——**初始化 SDL → 建窗口 → 建渲染器**。这是引擎与操作系统/窗口系统打交道的起点。

改动很小（两个文件），但牵出几个 SDL3 的关键 API，以及一个**本集刻意留下、下集要解决的结构性隐患**（窗口/渲染器目前是局部变量）。

> [!note] 课程用 SDL2，代码用 SDL3
> 本仓库已从 SDL2 迁移到 SDL3（见提交 `upgrade: migrate from SDL2 to SDL3`）。Pikuma 课程视频里演示的是 **SDL2** 语法，而我们的代码是 **SDL3**。本集涉及的三个 API 在 2→3 之间都有签名变化，下文会逐一点出，避免照搬视频写错。

## 核心概念

### 1. `SDL_main.h`：为什么 `main.cpp` 要单独 include 它

```cpp
// main.cpp
#include <iostream>
#include <SDL3/SDL_main.h>   // ← 只在含 main() 的文件里 include
#include "game.h"
```

SDL 提供了一套**跨平台的入口点适配**。在很多平台/构建方式下，程序的真实入口并不是标准的 `int main`（例如 Windows 子系统为 GUI 时的 `WinMain`）。SDL 的做法是：

- `<SDL3/SDL_main.h>` 把你的 `main` 宏重命名为 `SDL_main`；
- SDL 自带的 main 运行时库提供平台真实的入口，做完初始化后再回调你的 `SDL_main`。

因此规则很明确：

- **`#include <SDL3/SDL_main.h>`** —— 只放进**包含 `main()` 的那个翻译单元**（本项目的 `main.cpp`）。
- **`#include <SDL3/SDL.h>`** —— 任何需要调用 SDL API 的文件都可以 include（本项目的 `game.cpp` 用它来调 `SDL_Init` / `SDL_CreateWindow` 等）。

> [!important] 别把 `SDL_main.h` 撒得到处都是
> `SDL_main.h` 会把 `main` 重定义成宏。如果在一个**没有 `main` 但定义了名为 `main` 的函数/方法**的文件里 include 它，会引发诡异的编译错误。所以它只该出现在 `main.cpp`。

### 2. `SDL_Init`：初始化子系统

```cpp
if (!SDL_Init(SDL_INIT_VIDEO))
{
    std::cerr << "Error initializing SDL." << std::endl;
    return;
}
```

- `SDL_Init` 负责启动 SDL 库，传入的 flag 指定需要哪些子系统。
- `SDL_INIT_VIDEO` —— 视频子系统（建窗口、渲染必需），它会**连带初始化 events 子系统**，所以后面处理键盘/鼠标事件也不用单独 init。
- 返回值用 `if (!SDL_Init(...))` 判断失败——这正是 **SDL3 与 SDL2 的关键差异**：

> [!warning] SDL2 vs SDL3：`SDL_Init` 的返回值语义反了
> - **SDL2**：`SDL_Init` 返回 `int`，**0 表示成功，负数表示失败**。课程里会写成 `if (SDL_Init(SDL_INIT_VIDEO) < 0) { ... }`。
> - **SDL3**：`SDL_Init` 返回 **`bool`**，**`true` 表示成功**。所以代码里是 `if (!SDL_Init(...))`。
>
> 直接照抄课程的 `< 0` 写法在 SDL3 下语义会**正好相反**——成功时反而进错误分支。

### 3. `SDL_CreateWindow`：建一扇 800×600 的无边框窗

```cpp
SDL_Window *window = SDL_CreateWindow(nullptr, 800, 600, SDL_WINDOW_BORDERLESS);
if (!window)
{
    std::cerr << "Error creating SDL window." << std::endl;
    return;
}
```

- 窗口在创建的同时**立即显示**在屏幕上（SDL3 默认创建即显示，除非传 `SDL_WINDOW_HIDDEN`）。
- 四个参数：标题、宽、高、窗口标志位。
  - `nullptr` 标题 → 使用默认窗口标题；
  - `800, 600` → 宽 × 高；
  - `SDL_WINDOW_BORDERLESS` → 无标题栏、无边框的“裸”窗口。
- 失败返回 `NULL`，所以同样 `if (!window)` 判错。

> [!warning] SDL2 vs SDL3：`SDL_CreateWindow` 少了位置参数
> - **SDL2**：`SDL_CreateWindow(title, x, y, w, h, flags)` —— 要显式传位置 `x, y`（常用 `SDL_WINDOWPOS_CENTERED`）。
> - **SDL3**：`SDL_CreateWindow(title, w, h, flags)` —— **位置参数被移除**，窗口位置交给窗口管理器决定（macOS 上通常落在左上角附近）。需要居中时改用 `SDL_SetWindowPosition(window, SDL_WINDOWPOS_CENTERED, SDL_WINDOWPOS_CENTERED)`。

### 4. `SDL_CreateRenderer`：为窗口配一个 2D 渲染器

```cpp
SDL_Renderer *renderer = SDL_CreateRenderer(window, nullptr);
if (!renderer)
{
    std::cerr << "Error creating SDL renderer." << std::endl;
    return;
}
```

- 渲染器（renderer）是把“绘图指令”落到“窗口画面”上的上下文，后续所有绘制（清屏、画贴图、`SDL_RenderPresent`）都依赖它。
- 两个参数：关联的窗口、驱动名称。
  - `nullptr` 名称 → 让 SDL 选第一个可用的驱动（通常就是硬件加速的那个）。
- 失败返回 `NULL`。

> [!warning] SDL2 vs SDL3：`SDL_CreateRenderer` 从“索引+flags”变成“名字”
> - **SDL2**：`SDL_CreateRenderer(window, int index, Uint32 flags)`，例如 `SDL_CreateRenderer(window, -1, SDL_RENDERER_ACCELERATED)`（`-1` 表示挑第一个满足 flags 的驱动）。
> - **SDL3**：`SDL_CreateRenderer(window, const char *name)` —— **删掉了 flags，把整型 index 换成了字符串驱名**。传 `nullptr` 即用默认驱动。
>
> 课程里的 `-1` + `SDL_RENDERER_ACCELERATED` 在 SDL3 下已不适用。

## 一个本集刻意留下的结构性隐患

注意这三个对象的生命周期：

```cpp
void Game::Initialize()
{
    SDL_Init(SDL_INIT_VIDEO);
    SDL_Window *window = SDL_CreateWindow(...);    // ← 局部变量
    SDL_Renderer *renderer = SDL_CreateRenderer(window, nullptr);  // ← 局部变量
}   // ← 函数返回后，window / renderer 这两个指针就“丢了”
```

`window` 和 `renderer` 是 `Initialize()` 的**局部变量**——一旦函数返回，`Game` 对象再也拿不到它们。这带来三个后果：

1. **`Render()` 用不了渲染器**：它没有 renderer 的引用，目前是空的，下集要画东西时必须先让 renderer 成为可见成员。
2. **`Destroy()` 无法清理**：没法调用 `SDL_DestroyWindow` / `SDL_DestroyRenderer`，目前也无法调用 `SDL_Quit`。
3. **内存/句柄泄漏**：窗口和渲染器随程序结束才被 OS 回收。

这显然是**刻意的分步**：本集只验证“能建出来”，下一集自然会把它们提升为成员变量（如 `SDL_Window *mWindow;` / `SDL_Renderer *mRenderer;`），再在 `Destroy()` 里配对释放。这是典型的 [[RAII]] 思路在 C 风格 SDL 句柄上的手工投影。

## 运行效果与“第二个”死循环问题

把代码跑起来后你会看到：

- 一个 **800×600 的无边框窗口**闪出来（说明窗口确实建成了）；
- 然后程序**卡死**——既画不出东西，也关不掉窗口。


| 现象 | 根因 | 下一步修法 |
|------|------|-----------|
| 窗口内容空白 | `Render()` 是空的，从未调用 `SDL_SetRenderDrawColor` + `SDL_RenderClear` + `SDL_RenderPresent` | 在 `Render()` 里清屏并 present |
| 点窗口关闭无响应 | `ProcessInput()` 是空的，没有 `SDL_PollEvent` 处理 `SDL_EVENT_QUIT` | 引入事件循环 + `bool isRunning` 标志，收到关闭事件就置 false 打破 `while` |
| 即便初始化失败也会卡死 | `Initialize()` 失败只是 `return`，`main` 仍照常调用 `Run()` | 用 `isRunning` 在 `Initialize` 成功时才置 true，`Run()` 改为 `while (isRunning)` |

> [!important] `isRunning` 是下集的关键
> 把 `while (true)` 改成 `while (mIsRunning)`，让 `Initialize()` 成功才置位、`ProcessInput()` 收到退出事件才清位——这样才能正常走完 `Run()` → `Destroy()` → 析构，资源清理链才闭合。本集的“局部变量窗口”也会在那时一并升级为成员。

## 要点总结

- ✅ `main.cpp` 引入 `SDL3/SDL_main.h`，接上 SDL 的跨平台 main 入口（只在含 `main()` 的文件 include）。
- ✅ `Initialize()` 三步走：`SDL_Init(SDL_INIT_VIDEO)` → `SDL_CreateWindow(nullptr, 800, 600, SDL_WINDOW_BORDERLESS)` → `SDL_CreateRenderer(window, nullptr)`。
- ✅ 每步都 `if (!...)` 判错并 `std::cerr` 打日志后提前 return。
- ⚠️ 牢记 **SDL2 → SDL3** 三处签名变化：`SDL_Init` 返回 bool、`SDL_CreateWindow` 去掉位置参数、`SDL_CreateRenderer` 用名字串替代索引+flags——别照抄课程视频。
- ⏳ 窗口/渲染器目前是**局部变量**，下集需提升为 `Game` 成员，并在 `Destroy()` 里配对销毁 + `SDL_Quit`。
- ⏳ `Run()` 仍是死循环、`ProcessInput/Update/Render` 仍为空，等待 `isRunning` 标志 + 事件循环打破僵局。
